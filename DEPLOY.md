# Размещение в Яндекс Облаке

Сайт статический, поэтому раскладывается на две части:

| Часть | Сервис | Что делает |
|---|---|---|
| Страницы, стили, фото | **Object Storage** | отдаёт сайт |
| Приём заявок | **Cloud Functions** | отправляет заявку на почту |

Обе внутри РФ, что важно: сайт собирает имена и телефоны, а 152-ФЗ требует
хранить персональные данные россиян на серверах в России.

---

## 1. Почта для заявок

Заявки приходят на ящик, а не в мессенджер: 152-ФЗ требует хранить
персональные данные россиян в базах на территории РФ, а почта на
`yandex.ru` данные из страны не выводит.

Нужен **пароль приложения**, обычный пароль от почты Яндекс для SMTP
не принимает:

1. Зайти на [id.yandex.ru](https://id.yandex.ru) → «Безопасность».
2. «Пароли приложений» → выбрать «Почта».
3. Придумать название, например `soldout-site`.
4. Скопировать выданный пароль — второй раз он не покажется.

## 2. Функция приёма заявок

1. Консоль Яндекс Облака → **Cloud Functions** → «Создать функцию»,
   имя например `soldout-lead`.
2. Создать версию: среда выполнения **Node.js 18**, способ — «ZIP-архив»,
   загрузить `yandex-function.zip`.
3. **Точка входа:** `index.handler`
4. **Таймаут:** 10 секунд, **память:** 128 МБ — этого хватает.
5. Переменные окружения:

   | Имя | Значение |
   |---|---|
   | `MAIL_TO` | куда приходят заявки, например `soldout-loft@yandex.ru` |
   | `SMTP_USER` | ящик для отправки, обычно тот же |
   | `SMTP_PASS` | пароль приложения из пункта 1 |
   | `SMTP_HOST` | `smtp.yandex.ru` |
   | `SMTP_PORT` | `465` |
   | `ALLOW_ORIGIN` | адрес сайта, например `https://soloft.ru` |

6. На вкладке «Обзор» включить **«Публичная функция»** — иначе браузер
   получит отказ в доступе.
7. Скопировать ссылку для вызова, вид:
   `https://functions.yandexcloud.net/d4e********`

Пароль вводится **только здесь**, в переменных окружения. В код страницы он
не попадает: иначе его увидел бы любой посетитель через «просмотр исходника».

---

## 3. Адрес функции в сайте

В `index.html` найти строку:

    const LEAD_URL = 'api/lead.php';

и подставить ссылку из пункта 2.7:

    const LEAD_URL = 'https://functions.yandexcloud.net/d4e********';

---

## 4. Сайт в Object Storage

1. **Object Storage** → создать бакет, имя латиницей, например `soloft-ru`.
2. Доступ на чтение объектов — **публичный**.
3. Загрузить содержимое папки `upload`, сохраняя структуру:
   `index.html`, `privacy.html`, `agreement.html`, `assets/`, `favicon.svg`,
   `robots.txt`, `sitemap.xml`, `site.webmanifest`, иконки.
   Папку `api/` загружать не нужно — заявки обрабатывает функция.
4. Вкладка **«Веб-сайт»** → «Хостинг»:
   - главная страница: `index.html`
   - страница ошибки: `index.html`
5. Проверить по выданному адресу вида `soloft-ru.website.yandexcloud.net`.

---

## 5. Домен и HTTPS

Object Storage сам по себе HTTPS для своего домена не даёт, поэтому:

1. Подключить **Cloud CDN** к бакету.
2. В CDN указать домен `soloft.ru`, выпустить бесплатный сертификат
   Let's Encrypt.
3. У регистратора домена прописать CNAME на адрес, который выдаст CDN.

После смены домена поправить в `index.html` адреса `canonical`, `og:url`
и `og:image`, а также ссылку в `robots.txt` и `sitemap.xml`.

---

## 6. Проверка

Открыть сайт, заполнить форму, отправить. Письмо должно прийти на ящик из `MAIL_TO`.

Если не пришло — Cloud Functions → вкладка «Логи»: функция пишет туда причину
(нет переменных окружения, SMTP отклонил авторизацию и так далее).

Частые причины:
- в `SMTP_PASS` обычный пароль вместо пароля приложения — Яндекс откажет;
- функция не публичная — браузер получает отказ;
- в `ALLOW_ORIGIN` адрес не совпадает с тем, откуда открыт сайт;
- письмо ушло в «Спам» — проверьте папку.

---

## Запасной вариант

Если позже понадобится обычный хостинг с PHP (Timeweb, Beget, REG.RU),
в проекте лежит `api/lead.php` — тот же обработчик на PHP.
Тогда `LEAD_URL` возвращается на `'api/lead.php'`, а доступы вписываются
в `api/config.php` на сервере.
